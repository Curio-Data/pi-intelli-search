## Background to E1

**The problem.** The bundle declares an exact `engines.dsh: 0.2.2-rc.1` (PLAN.md Step 1, "initially exact ... because no broader range has evidence"). On 2026-11-20 the registry's `latest` and `next` for `@deepseek-ai/dsh` were both `0.2.2-rc.5`, so a fresh dsh installation is not `rc.1`. The pinned host's `dsh-plugin-manager` and `dsh-app-boot` READMEs say a bundle whose `engines.dsh` excludes the running version is refused at `dsh plugin add` and skipped at profile startup unless an exemption is granted; its `dsh-package-manifest` README says the field is not enforced. Refusal on `rc.5` is therefore inferred, not reproduced.

**How existing plugins handle it (Observed 2026-11-21, `npm view` and the pinned host).** No plugin publishes one package per dsh version. The host's own packages declare no `engines.dsh`, which imposes no constraint; the `dsh-app-boot` README says official bundles follow the DSH version. Of 16 third-party plugins sampled, 11 declare no `engines.dsh` and 5 declare a range: `>=0.2.2-rc.1 <0.3.0` (`dsh-plugin-trim`), `^0.2.2-rc.3` (`dsh-plugin-debugging`), `>=0.2.0-rc.0 <0.3.0-0` (`dsh-plugin-health`), `>=0.1.5-rc.1 <0.3.0` (`@99galaxy/dsh-plugin-market`) and `>=0.2.0` (`@woosau/dsh-custom-env`). Prereleases take part in range matching (`dsh-app-boot` README § Profiles). This repository's exact pin is the outlier.

**Options put to the owner:**

1. Declare a range over the preview line, such as `>=0.2.2-rc.1 <0.3.0`, as the proposal's catalogue row recommended (`docs/proposals/dsh-host-support-proposal.md`, the `engines.dsh` row of its decision table). Run scenario 18 on `rc.5` as well as `rc.1` before release, and say in the docs which versions were tested and that the range is declared, not tested throughout.
2. Keep the exact pin, pin the host version in every install instruction, and describe the refusal accurately.
3. Declare no `engines.dsh`, as most plugins do. No refusal ever happens, and nothing tells a user on an untested host that it is untested.

The coordinator recommended option 1, and the owner chose it (E1).

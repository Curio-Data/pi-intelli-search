# Codemode Study Publication Bundle

Offline numerical-analysis bundle generated by `scripts/benchmarks/study-publication.ts`. With the runtime and loader provisioned, regeneration makes no model call and does not read credentials or private sessions. Runtime dependencies are not bundled beyond the pinned manifest below; inspect [omissions.json](omissions.json) and the output before sharing.

## Layout

```
dataset.json           shareable sanitised dataset (frozen schema plus the declared additive fields)
derived/               analysis.json and effects.csv from the accepted analysis kernel
environment.json       environment pins and model identities available in the dataset or inputs manifest
omissions.json         redaction policy, known omissions and their stated reproducibility limits
provenance.json        input identity, build runtime, exporter commit and source hashes, scrub locations, private artefact digests
tables/                runs.csv, claims.csv, outcomes.csv and judges.csv (when scored records exist)
figures/               deterministic SVG figures, labelled with partition and availability
REPORT.md              generated claim-scoped analysis summary
inputs/                optional hash-checked publication inputs and their manifest
source/                analysis-kernel and exporter sources plus an ESM package.json marker
package.json, package-lock.json   pin the tsx loader for provisioning
MANIFEST.json          sha256 and size of every other file
```

## Provision Dependencies (Once)

Unpack the bundle inside a dedicated, empty reproduction directory containing no other project or files, and keep the bundle unchanged. The copy steps below replace manifests in the parent directory, so never run them inside an existing project; if the parent holds other work, preserve it and choose a new directory. Provision the pinned loader in that parent and write all reproduction output outside the bundle: dependencies or scratch files inside the bundle are unlisted files and make verification fail. With `bundle/` as the unpacked bundle directory, one level above it:

```bash
cp bundle/package.json bundle/package-lock.json .
npm ci        # may need network access or a populated npm cache; not part of offline regeneration
cd bundle
node --import tsx source/study-analysis.ts dataset.json ../analysis-check
node --import tsx source/study-publication.ts verify . ../verify-check
```

The loader resolves from the parent directory's `node_modules` (including its `.bin` symlinks), which sits outside the manifest-exact bundle. Both sibling check directories (`analysis-check`, `verify-check`) are disposable scratch and must be fresh for each run. Record the runtime and loader versions used for the independent reproduction and compare them against `buildRuntime` in `provenance.json` and the durable reproduction report. Bundle verification does not certify script-free provisioning: provisioning and its dependency hooks remain separate from the offline analysis commands. The recorded build runtime is not a compatibility floor.

## Integrity

`MANIFEST.json` records the SHA-256 digest and byte size of every other file. The bundled `verify` command checks the listed digests for `dataset.json`, `source/` and every other manifest entry, and cross-checks the recorded source hashes, input hashes and the manifest's own shape. Retain the manifest with the bundle; these checks establish consistency with that manifest and the invoked sources, not independent authenticity. Publish the digest of `MANIFEST.json` itself out of band alongside the bundle: that out-of-band digest is the external authenticity anchor.

## Column Dictionary (tables/runs.csv)

| Column | Meaning |
|---|---|
| `analysis_valid` | The kernel's paired-sample validity predicate: settled outcome, complete observation, observed catalogue, valid replay state |
| `valid_task_outcome` | Recorded flag: a failed run still counts as a settled task outcome (only meaningful for failed runs) |
| `failed_run_valid_outcome` | The same flag restricted to failed runs; empty for other statuses |
| `input_uncached`, `input_total` | Gated by `main_usage_complete` and `main_input_total_complete`; empty means unknown, never zero |
| `cache_read`, `cache_write` | Gated by `main_usage_complete`; empty means unknown, never zero |
| `error` | Free text, sanitised and truncated at 200 characters; a leading formula character (=, +, @ or a text-leading dash) is escaped with a prefixed apostrophe, so the cell can differ from the recorded error |
| `exposure_status` | `complete`, `incomplete`, `unavailable` or `absent` (no contextExposure record) |
| `raw_page_characters` | Complete-record total of retrieved-page characters in actual requests |
| `whole_page_characters` | Complete-record whole-page-or-long run characters |
| `short_run_characters` | Complete-record short exact page-text run characters (dataset field `quotationCharacters`); a size class, not a quotation judgement |
| `observed_*_characters` | Recorded lower bounds published for incomplete records; a recorded zero is a real zero, and empty means unavailable or absent |
| `reported_pipeline_usd` | Per-run provider-reported pipeline cost. Replay rows are fixture reproduction and excluded from the analysed cost endpoint |

## Limits

The bundle reproduces the numerical analysis and claim states. It does not carry private raw sessions, request captures, replay fixtures, judge packets or (unless supplied through the inputs manifest) task inputs, the corpus or the main-model identity; see `omissions.json` for every known omission and its stated effect. Full final answers are not assembled automatically; they can be attached through the inputs manifest. Judge rationales and evidence quotes contain answer passages that may have been sanitised, not guaranteed verbatim transcripts. Final answer assembly and source-backed checking remain coordinator-owned. A live rerun may produce different answers or search results; offline reproduction never promises identical remote-service outputs.

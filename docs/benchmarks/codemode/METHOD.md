Capabilities, descriptions, skill guidance and output filtering are disclosed treatment components. Compare platform/protocol populations separately; a Claude Code MCP main is not a native arm.

## Forced and Unforced Populations

Forced workflows use the corpus's exact `workflowQueries`, domains/focus, four attempted pages per research query and fixed supported arguments. Single-research tasks call one research. Multi-angle/breadth tasks call the listed research queries, with prescribed serial/parallel scheduling and recorded result-reduction choices. Freeze the complete script/prompt hashes before fixture capture. Maintain the same task intent, source/page allowances and final-answer budget; any smaller script-return budget is explicitly part of the treatment, not hidden evidence that computation itself saved context.

Replay through the actual registered native tool wrappers and real Codemode bridge, with all model/fetch/catalogue/suggestion responses, citations and usage fixed. Distinct identical requests have ordered occurrences and stable workflow nodes. Declare generated path/identity bindings; do not rewrite arbitrary code/source text. Misses stop and invalidate the affected replay block without live fallback. Loader/module identity is proved with a credential-free scripted main before paid capture.

Live unforced sessions receive task intent rather than tool/function names, preserving routing and automatic skill discovery as observations. B sessions that choose direct tools remain in B's unforced population. Their novel arguments are not judged against the forced fixture dictionary. Explicit skill invocation is a separate diagnostic, not evidence of automatic discovery. Do not mix forced replay and unforced live outcomes into one estimator.

## Hypotheses and Observation

- H1: At least 50% lower main-model uncached input for the prespecified multi-angle/breadth population. B/A2 activation ratio is primary; B/A whole-intervention ratio is secondary. Report uncertainty rather than point-estimate success.
- H2: Single-research B/A2 token equivalence under a later owner-approved ratio margin. B/A is secondary. Absence of a significant difference is not equivalence.
- H3: No raw intermediate-page exposure in actual main requests for the specified workflow. Justified quotations are separately labelled.
- H4: Final-answer quality is non-inferior under a later meaningful-loss margin, not a two-sided sameness claim.

Use read-only actual-request capture and canonical assistant/tool usage events. Scan request arguments/results, script output, console/error output and spill-file follow-up for distinctive synthetic/source overlaps. Events can contain raw pages without putting them into the next model request; do not count those bytes as leakage automatically. A context-exposure check is not a prompt-injection security proof.

Main tokens come from assistant-message usage; pipeline usage comes from canonical tool results, without repeated turn/parent/nested totals. Preserve cache components, missing usage, cancelled-parent delivery gaps and both judges' results. Report query-level paired distributions; preserve raw observations for later exploratory margin sensitivity.

## Host and Isolation

Use pre-configured encrypted worktrees and supported overrides. Pin host/source/lockfile/model/settings/tools/skills/prompts, capture the actual main request tool catalogue and verify no unrelated global extension changes the arm. Codemode-off native arms omit the built-in Codemode extension; B/C explicitly enable it with frozen mode/inline budget. The private observer is explicit and identical across paired arms. No separate isolation framework or credential copying is required.

Native output schemas/full structured data, script-only fetch, finite script timeouts, cancellation and lifecycle-safe widget are R2 capabilities. R1 must already provide their fetch/result/progress/accounting prerequisites, proved by the temporary wrapper dry run. No shared-core/MCP repair is permitted in R2.

## Judging and Claims

Both subscription judges receive identical blinded evidence and balanced pair order in fresh sessions. Calibrate against disjoint human-checked material, preserve disagreement and analyse the Sol main/judge identity as a possible bias. No judge sees the other judge's output. Preserve failed/incomplete sessions; two judge calls do not create two independent task samples.

The corpus's confirmation reserve is not a powered sample. After the exploratory pilot, D6 must select margins, fresh-series size/precision and the final confidence/multiplicity method before new confirmation runs. D7 must precede an arm-D study if a separate structured-output causal claim is desired. Otherwise omit that claim. A budget-limited exploratory programme is useful evidence but is not the completed confirmatory programme.
